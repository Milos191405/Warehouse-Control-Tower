# Warehouse Control Tower

A data analytics and warehouse operations project based on a
synthetic simulation of a distribution center in Heidelberg, Germany.

## Project Overview

This project simulates warehouse operations from inventory and
order creation to picking, packing, and shipping.

The goal is to build an end-to-end analytics solution for monitoring
warehouse performance, inventory, order fulfillment, picking,
packing, and shipping operations.

The project is developed incrementally, starting with warehouse
modeling and synthetic data generation and progressing toward
PostgreSQL, SQL analytics, Power BI, and Microsoft Fabric.

## Project Goals

- Model a realistic warehouse structure
- Generate synthetic warehouse data with Python
- Use a real-world product catalog as the product data reference
- Build a relational warehouse data model
- Store and transform data using PostgreSQL
- Develop analytical SQL queries and KPIs
- Build a Power BI Warehouse Control Tower
- Integrate Microsoft Fabric
- Analyze warehouse performance and operational bottlenecks

## Project Background

The warehouse model is based on a real-world industrial warehouse
environment and uses its storage capacity as a reference for the
synthetic simulation.

The project does not include company systems, customer data, order
data, credentials, or other confidential business data.

All operational warehouse data generated for the project is
synthetic.

## Warehouse

The simulated warehouse consists of three halls:

- Hall 1
- Hall 2
- Hall 3

Total modeled storage capacity:

**24,180 storage positions**

The warehouse model includes:

- High racks
- Low pallet storage
- Vertical lifts
- Picking cart areas
- Cart picking
- Forklift picking
- Stapler picking
- Packing stations
- Boxes and containers
- Picking carts
- Pallets

Packing stations are modeled separately from warehouse storage
locations and are therefore not included in the 24,180 storage
positions.

## Warehouse Process

The main operational flow is:

**Order → Picking → Packing → Shipping**

The project models:

- Storage locations
- Products
- Inventory
- Orders
- Order items
- Containers
- Picking operations
- Packing operations
- Shipping operations

Products can be stored in multiple warehouse locations.

Warehouse locations and containers can be scanned during
the picking and packing processes.

## Packing

The project includes different packing scenarios:

- Small packages
- Large packages
- Pallet shipments

Packing stations are modeled separately from warehouse
storage locations.

The current synthetic dataset contains small-package and
pallet-shipment scenarios. Large-package logic is implemented
in the packing model but is not currently represented in the
generated dataset.

## Data Source

The product data used in the synthetic simulation is based on
publicly available ABB product master data.

ABB product data is used only as a reference for available
product attributes such as:

- Product identifiers
- Product descriptions
- Dimensions
- Packaging information
- Other available physical characteristics

The operational warehouse data generated in this project is
fully synthetic and is not based on ABB operational or
transactional data.

No ABB customer, order, inventory, warehouse transaction,
credential, or other confidential business data is included.

Source:

- [ABB Article Master Data](https://new.abb.com/low-voltage/de/artikelstammdaten/niederspannung)

## Data Pipeline

The project uses a layered data architecture:

**ABB Product Catalog → Python Data Generation → Processed Data
→ Bronze → PostgreSQL → Silver → Gold → Power BI**

### Processed

The `data/processed/` layer contains validated synthetic
operational datasets generated by Python.

Current datasets include:

- `product_master.csv`
- `locations.csv`
- `inventory.csv`
- `orders.csv`
- `order_items.csv`
- `picking.csv`
- `packing.csv`
- `shipping.csv`

### Bronze

The `data/bronze/` layer contains controlled data-quality issues
introduced for the purpose of testing data cleaning and
transformation workflows.

Examples include:

- Whitespace inconsistencies
- Missing values
- Category inconsistencies
- Duplicate records

The Bronze layer is loaded into PostgreSQL and serves as the
starting point for SQL-based data transformation.

### Silver

The Silver layer will contain cleaned and standardized data.

Planned activities include:

- Data type standardization
- Missing-value handling
- Duplicate handling
- Text normalization
- Referential integrity checks
- Business-rule validation

### Gold

The Gold layer will contain business-ready analytical datasets
for reporting and Power BI.

Planned outputs include:

- Inventory analytics
- Order fulfillment analytics
- Picking performance
- Packing performance
- Shipping performance
- Warehouse KPIs
